# Public release: beherouter + beheaxi — design

> **Date:** 2026-09-11
> **Status:** approved, awaiting implementation plan
> **Scope:** three repos — `beherouter` (this one), `beheaxi` (sibling), and the
> deployment in `$HOMELAB_REPO/ur/service/beherouter/`.

## 1. Why

beherouter is to become a public open-source project on GitHub. That is not one
change but four coupled ones: the repo must be *installable* by a stranger, it
must not disclose the homelab it happens to run on, it needs documentation
written for a reader who has never seen it, and the deployment must stop
depending on a hand-copy step that only works from inside the umbrella checkout.

The four are coupled through a single fact: **`beheaxi` is a private hard
dependency.** Publishing beherouter without publishing beheaxi produces a repo
nobody can install, and the vendoring workaround that exists to avoid needing a
GitHub token at image-build time is the same thing that makes deployment
awkward. Resolving the dependency resolves both.

## 3. Decisions

Each was settled explicitly; the rationale is recorded so it is not re-litigated.

| Decision | Choice | Why |
|---|---|---|
| The `beheaxi` dependency | **Publish beheaxi too** | A public clone then installs unaided, and it collapses the vendoring fork that makes deployment awkward. Vendoring beheaxi into beherouter would publish the code anyway while hiding only the repo. |
| Homelab detail | **Genericize identifiers, keep the lessons** | The operational traps (podman-network reachability, the Django underscore `Host` rule, the LibreChat 401-as-OAuth quirk) are the repo's real value. Only identifiers change. |
| Deployment | **Install-from-git + one deploy entrypoint** | Deletes four duplicated artifacts and the hand-copy step, and fixes the two documented outage modes. Image-registry CD is a clean follow-on, not a prerequisite. |
| Reach | **All three repos this cycle** | Written in-tree in each checkout; committing stays with the owner per repo. |
| Licence | **Stock Apache 2.0 + strong NOTICE** | Apache 2.0 cannot compel a user-agreement mention; §4(d) NOTICE propagation is the strongest *enforceable* attribution available, and stays OSI-approved and permissive. |

### 3.1 On the licence, explicitly

Apache 2.0 §4(d) binds any distributor of a derivative work to reproduce the
`NOTICE` attribution notices in at least one of: their own NOTICE file, their
source or documentation, or **within a display generated by the derivative work,
wherever third-party notices normally appear.** That is enforceable and it lands
where products keep legal attributions.

It does **not** name end-user agreements. Requiring that would mean an added
clause, which (a) may not bear the Apache name under Apache's own policy, (b)
revives the BSD 4-clause advertising pattern abandoned in 1999 because the
obligations multiply per dependency, and (c) is what corporate legal review
flags — the opposite of what permissive licensing buys. The user-agreement
mention is therefore a **documented request**, clearly labelled as not being a
licence term.

Apache 2.0 §6 grants no trademark rights, so "Behemotion" and the product names
remain protected independently.

## 4. Workstream A — publish beheaxi

Smallest piece, and it gates everything. beheaxi is already close: 30 tracked
files, **zero** internal identifiers, clean history, and CI that already runs
ruff + `mypy --strict` + pytest + self-conformance.

- Add `LICENSE` — stock Apache 2.0.
- Add `NOTICE`:
  ```
  beheaxi
  Copyright 2026 Behemotion (https://behemotion.com)

  Principal developer: Aleksandr Mezin

  This product includes software developed by Behemotion
  (https://behemotion.com).
  ```
- `pyproject.toml`: add `license = "Apache-2.0"` and
  `license-files = ["LICENSE", "NOTICE"]`.
- `.gitignore`: add `CLAUDE.md`, `HANDOFF.md`, `HARNESS-DIVERGENCES.md`,
  `.claude/` — they are untracked today, which is not the same as safe.
- Add an `## Attribution` section to `README.md` (same wording as beherouter's).
- Commit the currently-modified `uv.lock`.
- **Tag and push `v0.1.2`.** This is not optional bookkeeping. The existing
  `v0.1.1` tag points at `ff2f997`, which **predates the licence work** — a
  wheel built from `v0.1.1` would carry no `LICENSE` and no `NOTICE`, so the
  §4(d) attribution would never travel to a downstream consumer. The licence
  commit must be released before anything can depend on it.
- Flip the repo to public. **No PyPI publish** — a git tag suffices.

## 5. Workstream B — beherouter publishability

### 5.1 Licence artifacts

- `LICENSE` — stock Apache 2.0, byte-identical to beheaxi's.
- `NOTICE` — as in § 4 but naming `beherouter`.
- `pyproject.toml`: `license = "MIT"` → `license = "Apache-2.0"`, plus
  `license-files = ["LICENSE", "NOTICE"]`.

⚠️ `license-files` is load-bearing, not cosmetic: without it the NOTICE ships in
the git repo but **not** in the built wheel, so anyone installing beherouter as
a dependency never receives the file whose reproduction §4(d) obligates. Verify
the pinned hatchling supports PEP 639 `license-files`; fallback is
`[tool.hatch.build] force-include`.

### 5.2 Make a standalone clone install

Three coupled edits, and the lockfile is the one that is easy to miss:

1. Drop `[tool.uv.sources] beheaxi = { path = "../beheaxi", editable = true }`
   from `pyproject.toml`. This line is why `git clone && uv sync` fails for
   everyone outside the umbrella layout — including this repo's own future CI.
2. Move the dependency pin from `@v0.1.1` to **`@v0.1.2`** (the beheaxi release
   created in § 4). The existing comment explaining why `v0.1.1` is a *floor*
   rather than a preference — `v0.1.0` catches only one of the two importable
   `ClickException` classes, so usage errors exit 1 instead of 2 and conformance
   fails — still holds and must be preserved; `v0.1.2` is simply the first
   release that also carries the licence files.
3. **Regenerate `uv.lock`.** `uv.lock:88` currently reads
   `source = { editable = "../beheaxi" }`, so the *lockfile itself* encodes the
   local path, not just `pyproject.toml`. Fixing only the pyproject would leave
   a clean clone still broken, and the Containerfile's `uv sync --frozen`
   consumes exactly this lockfile — so the regenerated lock is what ships.

A developer who wants to hack on beheaxi locally installs it editable after
sync; that is a per-developer convenience and must not live in shipped
metadata.

### 5.3 Fix the hardcoded homelab URL (code, not docs)

`src/beherouter/cli/app.py:208` currently defaults `client-config`'s `base_url`
to the live homelab vhost. For a public tool that is a **correctness** bug, not
a disclosure one: every stranger running the generator gets a config pointing at
someone else's gateway.

- Default becomes `http://localhost:47100` (the app's own documented port).
- Overridable by `BEHEROUTER_PUBLIC_URL`.
- `--base-url` continues to win over both.
- `tests/test_clientconfig.py` (lines 6 and 18 reference the vhost) is updated to
  assert the generic default, the env override, and the flag's precedence.

### 5.4 The scrub

Placeholder vocabulary, applied consistently: `<SERVICE_HOST>`,
`gateway.example.com`, `$HOMELAB_REPO`, `<VAULT_KEY>`.

**Scrubbed** (live documentation): `README.md`, `CLAUDE.md`,
`HARNESS-DIVERGENCES.md`, `docs/DESIGN.md`, `docs/CALENDAR-BOOTSTRAP.md`, and
the 7 affected files under `docs/superpowers/specs/`.

**Excluded from publication instead of scrubbed** — added to `.gitignore`:

- `docs/superpowers/plans/` — 87 of the 174 hits. Execution checklists with no
  value to a public reader, and rewriting a historical SDD record to remove a
  hostname *falsifies* it.
- `docs/handoffs/` — 12 files of internal handoff prose.
- `local-infra/` — already documented as untracked by design; make it explicit.

**Preserved verbatim:** every trap, warning and lesson. Only identifiers change.

`CLAUDE.md` stays tracked and public after scrubbing: it is 25 KB of genuinely
good engineering documentation and the file that makes this repo workable by an
agent.

### 5.6 CI

Add `.github/workflows/ci.yml`, modelled on beheaxi's existing workflow:

1. `uv sync` — **in a clean clone**, which is the actual regression guard for

2. `uv run ruff check .`
3. `uv run pytest -q`
4. `uv run beheaxi conformance "beherouter" --json`

`452` → `466` in `CLAUDE.md:37`. Verified 2026-09-11: that is the **only**
occurrence in a tracked file — `README.md` states no test count.

## 6. Workstream C — the docs set

| File | Role |
|---|---|
| `README.md` | Public front door: what it is, the two faces, quickstart (install → `registry.toml` → `serve`), the operator-command table, `## Attribution`, links. No homelab specifics. |
| `docs/PLUGINS.md` | **New.** Plugin authoring guide. |
| `docs/DEPLOYMENT.md` | **New**, replaces `deploy.md`. |

### 6.1 `docs/PLUGINS.md` must cover

- The contract: a frozen `PluginSpec` plus one `async build(ctx) -> Backend`.
- **Why the spec must stay inert** — it is what lets `plugins`, `plugin-config`
  and `registry-lint` read a plugin without attaching anything, and what makes
  "attach performs no network I/O" mechanically enforceable rather than a
  convention. A plugin *cannot* phone home from its spec, only from `build`.
- The four backings: `http`, `stdio`, `cli`, `native`.
- `pinned`, `probe` and `probe_args` as **overrides of a tested default**, and
  that they resolve as one unit (an entry naming its own `probe` supplies its
  own `probe_args`) — with the `gitea-home` failure as the worked motivation.
- `ConfigField` / `EnvVar`, and that `EnvVar` names a credential *logically* so
  an operator never needs the backend's own variable name.
- `validate(config)` for enforcing a backend's quirks at config time, using
  plane's underscore-in-`Host` rule as the example.
- `catalogue_ttl_ms`, and the distinction that matters: the searchable catalogue
  refreshes on a TTL, while the **published `tools` array is frozen at attach**
  so a host's prompt cache is never invalidated.
- A worked end-to-end example, from `PluginSpec` to registry entry.
- How to test a plugin (the existing `tests/test_plugin_*.py` as the pattern).
- `plugin-config <surface> <plugin>` emitting all three plumbing fragments from
  one spec so they cannot disagree.
- The reusable corollary: a backend's catalogue advertises the **commercial**
  surface, so "the tool exists" says nothing about whether this deployment
  serves it. **Probe before pinning; re-probe after an upgrade or edition
  change.**
- ⚠️ An entry may not be committed before its secret exists: an unset `${VAR}`
  raises during `build_surfaces`, i.e. at startup, so it yields a **dead
  gateway**, `/healthz` included — not a broken surface.

### 6.2 `docs/DEPLOYMENT.md` must cover

Generic deployment first: container image, required env, `registry.toml`,
reverse proxy with bearer auth, `/healthz`, `health --deep --json` and its exit
codes, the pre-deploy `registry-lint` gate, verification, rollback.

Then a genericized **reference deployment** appendix (rootless Podman + systemd
user unit + linger + Caddy, ansible-driven), carrying the warnings that
generalize:

- ⚠️ An attach failure **crash-loops the whole gateway**, taking every other
  surface and `/healthz` with it.
- ⚠️ A same-host backend needs the shared container network. A rootless bridged
  container cannot reach a port published on its own host, so co-location makes
  a backend *harder* to reach, not easier.
- ⚠️ Per-surface plumbing is **three edits, not one** — registry entry, proxy
  authorization clause, env line. Registry alone → unreachable (default-deny);
  registry + env without the proxy clause → it answers to another client's
  token.

The dead dev-4 appendix in `deploy.md` is deleted, not carried over.

## 7. Workstream D — deployment simplification

Depends on Workstream A: install-from-git only works once beheaxi is public.

### 7.1 Install-from-git kills the duplication

The deploy directory currently duplicates `src/`, `vendor/beheaxi`,
`pyproject.toml` and `uv.lock`. The two pyprojects are **deliberately**
divergent — the deploy copy depends on `vendor/beheaxi` by path specifically so
`podman-compose` needs no GitHub credentials. With beheaxi public that entire
reason disappears.

The Containerfile's `COPY pyproject.toml uv.lock README.md` + `COPY vendor` +
`COPY src` becomes:

```dockerfile
ARG BEHEROUTER_VERSION=v0.1.0
RUN git clone --depth 1 --branch ${BEHEROUTER_VERSION} \
      https://github.com/behemotion/beherouter /src \
 && cd /src && uv sync --frozen --no-dev
```

⚠️ **Prerequisite: beherouter currently has no git tags at all** — none local,
none on the remote. `git clone --branch v0.1.0` cannot resolve today. A release
tag must be created and pushed (after Workstream B lands, so the tag carries the
licence, the regenerated lockfile and the generic `client-config` default), and
`BEHEROUTER_VERSION` must name that tag. Deploying an untagged `main` is
explicitly not the design: the whole point is that the image is built from an
immutable, tested revision.

Verified feasible: the build already has egress — it curls `gitea.com` for
gitea-mcp, pulls `ghcr.io/astral-sh/uv`, and `uv pip install`s
plane-mcp-server from PyPI.

`--frozen` is **preserved**, and that is the point. A naive
`pip install beherouter @ git+...` would re-resolve and ship something other
than what was tested; cloning the tag brings the tag's own `uv.lock`, so the
image gets the tested resolution with no vendoring. Deploying becomes "bump
`BEHEROUTER_VERSION`".

Four duplicated artifacts and the hand-copy step are deleted.

### 7.2 One deploy entrypoint

⚠️ **Corrected 2026-09-11 after reading the playbook.** An earlier draft of this
section proposed adding a build-before-switch ordering and a `registry-lint`
pre-flight. **Both already exist and are correct.** `playbooks/service.yml`
runs, in this order: copy build-context root files → sync `src/`/`vendor/` →
rebuild the image when build inputs changed → **`registry-lint` inside the
freshly built image** → restart. Its own comment states the intent precisely:
"Failing here aborts the play with the old container still running and still
serving — the bad registry never reaches the service." The 2026-09-08 ordering
hazard is **closed**; this design must not reimplement it.

What is genuinely missing is three things:

1. **The proxy playbook is a separate play.** `playbooks/caddy.yml` is
   `hosts: caddy`, not `hosts: service`, so it *cannot* become a task inside
   `service.yml`'s play, and `import_playbook` cannot force `--tags beherouter`
   onto an imported play. A shell wrapper is therefore the correct mechanism,
   not an ansible refactor.
2. **No post-deploy verification.** Nothing checks `/healthz` or
   `health --deep --json` after the restart.
3. **No rollback.**

So the entrypoint — `$HOMELAB_REPO/ur/service/beherouter/deploy.sh` — is a thin
wrapper that runs:

1. `ansible-playbook playbooks/service.yml --tags beherouter`
   (which already performs copy → build → registry-lint pre-flight → restart)
2. `ansible-playbook playbooks/caddy.yml -l service` — **unconditionally**
3. verify `/healthz` **and** `beherouter health --deep --json`, asserting
   `attach: ok` + `probe: ok` for every surface
4. on failure, roll back by rebuilding the previous `BEHEROUTER_VERSION` tag

Step 2 being unconditional is the fix for a real incident: on 2026-07-30 the
gateway had dropped `gitea-home` while the proxy still honored its token, so a
retired token passed the edge and collected 404s instead of being refused. A
stale authorization clause would authorize that old token against whatever
surface later claims the same path.

Step 3 is the one this deployment has never had: today a successful playbook run
proves the container restarted, not that any surface actually works.

## 8. Workstream E — flip beherouter public

Last, and only after CI is green on a clean clone. Set a description and topics;
confirm GitHub detects Apache-2.0 from the LICENSE file.

## 9. Testing

- **All 466 existing tests stay green.** ruff clean. Conformance 6/6.
- **New unit tests** for § 5.3: the generic `client-config` default, the
  `BEHEROUTER_PUBLIC_URL` override, and `--base-url` precedence over both.
- **New enforcement test** — a repo-hygiene test asserting no *tracked* file
  matches the internal-identifier patterns (the two host subnets, the private
  domain, the homelab repo path, the credential-ledger filename, and an
  absolute home path that would leak a username). This converts the scrub from a one-time cleanup into a
  mechanical invariant, in the style this repo already uses to enforce the Plane
  CE 404s and the Microsoft `consumers` authority.
- **CI clean-clone job** proves standalone installability on every push — the
  regression that would otherwise only be discovered by a stranger.
- The deploy entrypoint is verified by running it against the live service and
  confirming `/healthz` plus `attach: ok` + `probe: ok` for both surfaces.

## 10. Out of scope (YAGNI)

PyPI publishing · a `ghcr.io` image registry and pull-based CD · out-of-tree
plugin discovery via entry points · rewriting historical plans and specs ·
re-attaching `gitea-home` (needs a freshly minted PAT) · the calendar OAuth
consent bootstrap · any new plugin or surface.

## 11. Risks

| Risk | Mitigation |
|---|---|
| beheaxi public before beherouter leaves a visible asymmetry | Harmless and brief; sequencing is dependency-forced. |
| `license-files` unsupported by the pinned hatchling → NOTICE absent from the wheel | Verify before relying on it; fall back to `force-include`. |
| The scrub misses an identifier | The § 9 enforcement test fails the build rather than trusting review. |
| Install-from-git needs build-time egress to github.com | Already verified present (gitea.com, ghcr.io, PyPI all reached today). |
| Tag ordering: a tag cut before the licence/lockfile commits ships a wheel with no NOTICE and a lock that points at `../beheaxi` | Tags are cut *after* their workstream lands, never before — beheaxi `v0.1.2` after § 4, beherouter's first tag after § 5. |
| A public `CLAUDE.md` is a candid internal engineering log | Accepted deliberately after scrubbing; it is the file that makes the repo workable. |
| Deleting the vendored copy removes the current rollback path | The deploy entrypoint rolls back by rebuilding the previous `BEHEROUTER_VERSION` tag, which is a stronger guarantee than a mutable directory. |

## 12. Sequence

```
A (beheaxi public)
  LICENSE + NOTICE + metadata --> tag v0.1.2 --> flip public
      |
      |  (beherouter cannot resolve its dep until v0.1.2 exists and is public)
      v
B (beherouter publishability)
  LICENSE + NOTICE, drop uv.sources, pin @v0.1.2, regenerate uv.lock,
  fix client-config default, scrub, CI          --> tag v0.1.x
      |                                              |
      +--> C (docs: README, PLUGINS, DEPLOYMENT)     |
      |                                              |
      +--> D (deploy: install-from-git needs that tag)
                                                     |
                                                     v
                                              E (flip beherouter public)
```

Both tag steps are hard gates, not conveniences: § 7.1 clones a tag, and § 5.2
depends on a beheaxi tag that carries the licence files.
